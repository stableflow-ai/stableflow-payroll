Stableflow Payroll

使用文档

Stableflow Payroll 是一个面向组织和团队的轻量化财务管理平台，核心支付能力包括指定支付和批量支付，用于集中管理资金、付款及成员协作事务。平台提供组织者和成员两端：组织者管理并发放工资单、报销、奖金等，成员端则可提交报销、查看收入。

1 平台概览

Stableflow Payroll 帮助企业用一个付款钱包，向 EVM、Near、Solana、Tron、Zcash 上的收款地址发放稳定币。若用 Zcash 原生资产 作为付款来源，需连接 Noir Wallet。

付款在你自己的钱包里完成（自托管）：单笔付款跳转到托管结账页，按表单批量付款在应用内签名确认。

2 登录、注册

首次使用时，在注册页完成账户认证并创建组织，您将以组织者身份进入管理平台；成员通过组织发来的邀请链接加入。若组织启用了 Google 登录，两种注册都可以改用 Google 账号。

2.1 邮箱登录

  1. 填写 Sign in by Email（邮箱，最长 100 个字符，需符合邮箱格式）。
  2. 填写 Password（8–50 个字符）。
  3. 点击 Sign in。

其他入口

  • Forgot Password?：打开重置密码弹窗（见 2.5）。
  • Sign in with Google：见 2.3（需组织已启用）。
  • Create an account：进入管理员注册。

2.2 注册组织（管理员）

这是管理员专用注册，邀请码必填。该页没有 Google 按钮，成员请使用组织发来的邀请链接。

第一步：Create account

字段 规则
Your name 必填，最长 50
Email 必填，最长 100，需合法邮箱
Password 8–50 个字符
Confirm Password 必须与密码一致
Invite code 必填，最长 10

点击 Continue 进入第二步。

已有账号可点 Sign in 回到登录。

第二步：组织信息

字段 规则
Organization Name 必填，最长 50
Logo URL 可选；若填写须为 http(s) URL，最长 500
  • Back：返回第一步，两边已填内容都会保留。
  • Create Organization：提交注册，成功后进入 Overview。

2.3 Google 登录、绑定与注册

若组织启用了 Google 登录，登录页和邀请注册第一步会显示 Sign in with Google。

点击后走 Google Identity 弹窗完成授权。

已注册的 Google 账号：直接登录成功，效果与邮箱登录相同。

未注册的 Google 账号

弹出 Google account not registered：

  • Register（左侧，次按钮）：去创建新账号。
  • Bind（右侧，主按钮）：把 Google 账号绑定到已有邮箱。

绑定已有邮箱

  1. 填写要绑定的 Email（可预填 Google 邮箱）。
  2. 点 Send Code，邮箱收到验证码（60 秒冷却）。
  3. 填写验证码，提交绑定。
  4. 成功后自动登录并进入 Overview。

管理员 Google 注册

从登录页未注册弹窗点 Register 进入。单页填写：

  • Name（预填 Google 姓名）
  • Invite code
  • Organization name
  • Logo URL（可选）

提交后创建管理员账号与组织。

成员 Google 注册

从邀请页未注册弹窗点 Register 进入。预填姓名，再填写职位以及组织 Integration 要求的钱包 / 通知字段，提交后以成员身份加入该组织。

邮箱注册流程没有 Google 按钮；管理员如需用 Google，请从登录页走「Sign in with Google → Register」。

2.4 邀请加入（成员）

邀请链接由管理员在 Team 或 Settings → Organization 点 Invite 复制。

已有账号请先登录自己的组织，再打开邀请链接加入。

第一步：Sign up

填写 Email、Password、Confirm New Password，点 Sign up。也可 Sign in with Google。

第二步：Profile Setting

顶部显示组织名、Logo 和第一步的邮箱。Back 回到第一步，两边内容都保留。

固定字段：

  • Name（必填，最长 50）
  • Position（可选，最长 50）

其余字段由组织 Integration 决定：

  • 钱包：EVM（必填）、SOLANA、NEAR、Tron —— 仅在该通道开启时出现；标为 Required 的必须填写，且地址格式必须匹配对应链。
  • 通知：Email / Telegram / Slack —— 仅在开启时出现。Email 通道开启时不会再问一遍邮箱，直接复用第一步的账号邮箱。

点 Continue 完成注册并进入 Overview。

2.5 忘记密码 / 修改密码

未登录（登录页 Forgot Password?）

  1. 输入邮箱，点发送验证码（成功 toast：Verification code sent，60 秒后可重发）。
  2. 输入验证码、新密码、确认新密码。
  3. 提交后密码被重置，之后用新密码登录。

已登录（账号菜单 Reset Password，或 Settings → Profile）

填写当前密码、新密码、确认新密码后提交。不走邮箱验证码。

账号菜单还提供 Logout。

3 主界面与导航使用

3.1 侧边栏

管理员

  • Overview（总览）
  • Payment（付款）
  • Operations（场景）：Payroll、Expense、Bonus，以及已启用的运营分类（如 Office、Procurement 等）
  • Team（团队）
  • History（历史记录）
  • Settings（设置）

成员

  • Overview（总览）
  • Payment（付款，仅单笔付款，没有「按表单付款」标签）
  • Expenses（费用）：Request Payment、Requests
  • History（历史记录）
  • Settings（设置，仅个人资料）

3.2 概览 Overview

总览页主体包含关键金额 / 指标、时间趋势折线图和右侧近期事项区域。这些信息适合用于日常启动检查：掌握总金额变化与日 / 月 / 年度支付变化，看清近期待办或活动，随后按需要进入付款、费用或历史记录模块处理具体事项。

包含：

  1. 组织摘要：组织名 / Logo、所有者、团队人数、Update Settings。
  2. Payments：Total Payment、Number of Payments，View all 跳转 History。面积图可切 Daily / Weekly / Monthly，以及 Volume / Transaction。
  3. High Priority：待办列表。点击可去 Payroll、Expense 或 History（失败付款）。

4 支付

Payment 下提供两种模式：Single Payment 与 Payment by Form。前者适用于一次性、信息明确的付款；后者适用于需要按页面表单收集或录入付款信息的场景。实际选用哪一种，应以组织当前流程及页面提供的字段为准。

单笔付款跳转到托管结账页完成；按表单付款需要先连接钱包，在应用内签名确认。

4.1 连接钱包

页面右上角：

  • 未连接：Connect Wallet
  • 已连接：链图标 + 缩短地址，点击可管理连接

支持的付款链类型：

  • EVM（RainbowKit）：Ethereum、Base、Arbitrum、Optimism、Polygon、BNB Chain、Avalanche、Gnosis、Scroll、X Layer、Berachain 等
  • Near
  • Solana
  • Tron
  • Zcash（Noir Wallet）：显示与报价付款地址为 shielded Unified（u1）；退款地址为透明地址（t1 / t3）

单笔付款（/pay）不需要连接钱包。 提交后跳转到托管结账页，在那边完成支付。

按表单付款、Payroll / Expense / Bonus / Operations 的 Pay Now 需要连接与「You Pay」所选链匹配的钱包，在本应用内签名。

Zcash 注意：

  • 原生 Zcash 付款只支持一名收款人的表单。多名收款人时 Zcash 选项可见但禁用，提示 Zcash does not support batch payments yet。
  • 正在确认中的入账 ZEC 不可花：会提示 ZEC is still confirming in Noir Wallet. Wait until it is spendable, then retry.
  • 收款地址可使用 Zcash t1 / t3 或 Unified u1 收取 ZEC。Sapling zs1 会被拒绝。

4.2 单笔支付 Single Payment

管理员可切换两种模式：

  • Single Payment → /pay
  • Payment by Form → /pay/form

成员看不到该切换。

单笔支付可通过输入收款钱包地址，或从 team 通讯录选择收款对象，再输入接收 Token & Chain 进行支付。可对该笔支付记录用途，仅对支付者可见，便于日后回顾。若开启通知，可以通过邮件或 Slack 等通知收款人。

填写

一张卡片：

  1. 收款人
    • 搜索或粘贴地址。
    • 打开通讯录：管理员看到的是有钱包的团队成员（滚动加载更多），只能选择，不能在这里增删。钱包展示顺序：EVM → Near → Solana → Tron。粘贴成员任一钱包仍会匹配姓名芯片。
    • 换到另一条链的地址会清空已选代币，再按 USDT → USDC → 该链第一个可用代币自动选默认币。
  2. 金额 + 收款代币（金额最多 6 位小数）。
  3. Purpose / Memo（可选，最长 200）。
  4. Notify Recipient：默认关。打开后出现可编辑邮箱（匹配到成员时预填）。发送时若开关打开但邮箱为空或非法，会拦截。

空表单按钮文案为 Starts from adding recipient；可发送时变为 Send Payment。

发送后发生什么

提交后会跳转到托管结账页完成支付。

从 Team 的行菜单点 Pay Now 也能发起单笔付款：姓名和钱包预填，地址仍可改。

4.3 按表单支付 Payment by Form

管理员专用。

根据业务需要，先管理 Operations 中的支付场景表单（如导入并管理 Payroll 表单），之后即可使用表单支付：选择对应的支付表单，实现批量支付。

这套表单也用于 Payroll / Expense / Bonus / Operations 的 Pay Now 弹窗。

选择表单

Form 下拉列出组织当前应付表：

  • Payroll
  • Reimbursement
  • Bonus
  • 动态运营分类（Office 等；标签优先用目录里的名称）

从成员的付款申请链接打开时，会预先选中对应的报销批次。

未选表时按钮文案为 Select Category。

You Pay

选表后选择付款钱包、链、代币。系统报价后，You Pay 与 Est. Cost 显示合计金额。

Total Valued 旁的 Details 打开抽屉：总金额、人数；工资表还有 Next Pay-date。每人显示姓名、邮箱、地址、付款偏好、Amount、Net Pay。

  • 仅工资表可 Edit / Save 改 Net Pay（最多 6 位小数）；保存只写入改过的行，关闭抽屉或换表会丢弃未保存的修改。
  • Expense / Bonus / Operations 的 Details 只读。
  • 拆批付完第一批后，Details 转为只读。

Notify Recipient

默认关。打开后右侧显示 {n} Email。点击打开 Notify Recipients 抽屉：总开关、每人一行姓名+邮箱+勾选。默认全选。无邮箱显示 -。关掉卡片开关、关掉抽屉开关、或取消所有勾选，都会关闭通知。

CSV 导入不会带出通知邮箱；只有条目上已有邮箱时才能通知。

发送

  • 单批：点 Send Payment，在钱包里签名确认。
  • 拆批（单批最多约 50 笔）：每个批次分别显示 Pay Now（Batch Payment n + 该批金额），逐批签名。表单保持打开，直到全部付完。
  • 额度不足时提示 Insufficient approval. Refreshing the quote. 并重新报价。

4.4 付款结果页

托管结账成功后回到这个页面。

成功后显示 Payment sent 和金额；处理中显示 Payment in progress。

页面展示收款金额、代币、网络、收款地址、时间，以及源链 / 目标链交易哈希（可点开区块浏览器）。底部可返回付款或历史。

4.5 支付后与批量限额

批量支付提交后，将逐条展示 transaction 交易结果，直至表单中所有的待支付项完成。如有失败交易，可到表单管理中再次支付。

⚠️ 注意：批量支付单次操作限制 50 条交易，如表单中待支付项超过 50，将被自动拆成多次支付动作。

与链、限额、导入模板相关的细节见 9.3 限额、链与常见注意。

5 Operations 管理模块

Stableflow Payroll 默认提供三个支付场景：Payroll / Expenses / Bonus，也可开启更多场景。额外场景来自运营目录。

5.1 工资单（Payroll）

Payroll 管理页包含关键参数、工资单月度趋势图表、近期 payouts 动态、Payroll 管理与编辑，以及 Payroll 支付历史。页面上方是统计与 Daily / Weekly / Monthly 总额图，以及最近发放列表，点一行可进入 History。

Next Payroll

列出下一次应发工资。行上在地址后显示邮箱。

空列表时出现创建区：

  • Download Template：下载 Excel（.xlsx），含 token / network 下拉。
  • Import CSV：从本地或 Google Docs 导入 CSV / Excel，最多 500 行。导入后打开 Add Payroll 抽屉并带入行。
  • Add Payroll / Add a new Payroll：打开空的 Add Payroll 抽屉。

初次编辑 Payroll，可根据平台提供的模版进行编辑和导入，也可手动录入表单。

抽屉可设发薪日：

  • First day of month
  • Last day of month
  • Day of month（1–31；选 1 或 31 等同于当月首日 / 末日）

Save 提交后留在 Next Payroll。Edit 打开 Edit Payroll，可改已有行、加新行、删除行。

Pay Now：打开按表单付款，表单名为 {月份} Payroll，并带入当前 Net Pay。未到发薪日时按钮显示 Not payday yet，点击不会打开。

Payroll History

分页历史，可 Export CSV。

View Details 打开右侧抽屉，抽屉旁的导出按钮下载这一次发放的 CSV。

状态：Failed、Expired、Paid、Pending。Failed / Expired 可点 Pay Again 重试。

若需要对工资相关操作进行追溯，应结合 Payroll 中的记录与 History 中的历史信息核对。

5.2 费用报销（Expenses）

Expenses 用于处理团队报销和费用支付管理。组织者可在 Open Expense 中批量导入或手动录入费用条目；Request Payments 中的条目来自成员的申请，组织者可根据核对金额和申请事由，对申请进行审核支付。

有未处理申请时，侧边栏会显示数量角标。

同样有统计、图表、最近发放（点一行进 History）。

Open Expense

按批次分组。单人批次直接显示 Title / Name / Purpose / Description / Address / Email / Payout Preference / Amount。多人批次先收起，Purpose / Description / Address / Email 显示 -，展开后看每人。Description 里的 http(s) URL 显示为带收据图标的链接，确认后新标签打开。

批次头上的 Pay Now 对该整批付款。

空列表时提供 Download Template、Import CSV、Add Expense；有批次时工具栏也有这三项。

导入规则与工资类似（最多 500 行，CSV 或 Excel）。Save 保存后回到 Open Expense。

Request Payments

一人一行。空列表显示 No payment requests。Pay Now 对该行所属整批付款，不是只付这一行。

Expense History

可搜索、按日期筛选。Export CSV 导出当前筛选结果。Description / Receipt 与申请列表相同。

状态：Failed、Expired、Paid、Pending。Failed / Expired 可 Pay Again。

5.3 奖金管理（Bonus）

支持批量导入和逐条录入，用于梳理团队的奖金表单。

⚠️ 注意：奖金很可能以项目币形式发放，在录入收款人钱包时，要判断该钱包地址是否可接受项目币 / 链。

结构与报销接近：统计、图表、最近发放、待付批次、历史。

空待付列表显示 Download Template、Import CSV、Add Bonus；有数据时工具栏同样有这三项。导入最多 500 行，Save 后回到待付页。

待付批次分组规则同 Open Expense。Bonus 列：单人显示 amount symbol ($volume)；多人展开后每人一行，表头仍显示批次美元合计。Description 中的 URL 同样可点。

正在付款的批次显示 Paying，其余显示 Pay Now。

历史为按人表格：Name / Purpose / Description / Bonus / Address / Payout Preference / Amount / Status。Failed / Expired 可 Pay Again。可 Export CSV。

5.4 更多场景（Manage Operations）

更多场景可通过点击 Operation 菜单旁的 ⋯（more）展开，例如：办公室运营费用 / 采购 / 外包 / KOL 市场宣传等。可点击查看该模块的表单模版，点击开启模块后，该模块将列入主菜单中作为常用表单管理功能。

运营目录里可能出现的分类举例：

  • Office
  • Procurement
  • Outsourcing
  • KOL&MKT
  • Grants
  • OTC Treasury

以及其他运营分类。

More Categories 抽屉

Operations 行右侧 ⋯ 打开分类抽屉。

每张卡片可预览模板：悬停出现 View Template，点卡片打开该分类模板，可返回网格。模板是示例行，不会真正付款。

  • 尚未加入：卡片 Switch 或模板 Add Category 会把分类加入组织。
  • 已加入：开关可在启用 / 停用之间切换。
  • 只有已启用的分类会出现在侧边栏；停用后该分类从侧边栏移除。
  • 模板上的 Add Category 会关闭抽屉并打开该分类页面。

分类页面

分类尚未启用时，页面显示说明、模板和 Add Category。启用后包含两个标签页：Payments 与 Payout History。

布局对齐报销：统计（Total Payment / Number of payments）、图表、最近发放、待付批次、历史。文案用目录名称（如 Add Payment / Import）。

空待付：Download Template、Import CSV、Add Payment。导入列：recipient,email,amount,token,network,memo，最多 500 行。Save 后留在 Payments。

历史可按日期筛选，没有搜索框。Failed / Expired 可 Pay Again。Pay Now 对该批次发起按表单付款。

6 团队（Team）

团队成员可由组织者手动添加，也可通过组织邀请成员。受邀请者通过邀请链接启用平台后，将自动归入该组织下；新用户需以邮箱注册账号加入组织。

顶部搜索（匹配姓名、邮箱、职位、EVM 地址），下方是分页表格（每页 10 人）。列：Name、Position、Email、Wallet。钱包优先显示 EVM，然后 Near、Solana、Tron。

右侧按钮与 Settings → Organization 相同：

  • Add Member：虚线框 + 加号，打开成员表单。
  • Invite：复制邀请链接发给成员。

添加 / 编辑成员

字段由 Integration 决定：

  • Name 始终显示（必填，最长 50）
  • Position 可选（最长 50）
  • 钱包与通知字段仅在对应通道开启时出现；Required 必须填。EVM 为必填。
  • 已填钱包必须通过该链地址校验（含 Tron）。
  • Telegram / Slack 填写后会保存；编辑时会预填已保存的值。

行菜单

  • Edit
  • Pay Now：发起单笔付款
  • Remove：确认后删除

7 历史记录（History）

管理员看到组织的全部记录，成员只看到自己的收支。

History 用于回查既往操作，是排查付款状态、确认是否已提交、核对工资、报销或奖金记录的重要入口。发生以下情形时，应优先查看历史记录：

  • 付款后页面状态不明确
  • 怀疑重复提交
  • 需要追溯某项业务依据
  • 需要确认某项操作的最终结果

顶栏

  • Search
  • 日期范围（默认最近 30 天）
  • Export CSV（导出当前筛选结果）

卡片内筛选

成员额外有 Type：All / Income / Payout。

然后：Source Network、Source Token、Destination Network、Destination Token、Status（All / Created / Processing / Completed / Failed / Expired）。

改任一筛选会回到第一页。没有金额筛选。

表格

列：Amount、Source、箭头、Received、Destination、From、To、Time、Status。

成员行最前加 Type（Income / Payout），金额带符号：收入绿色 +，支出红色 -。

Source / Destination 显示代币 Logo 与 SYMBOL · Chain。From / To 可复制缩短地址，并可打开对应链上的交易。

Status：Completed 绿色；Failed / Expired 红色；Created / Processing 黑色。

8 设置（Settings）

Settings 可设置组织信息、配置成员必填信息等。Integration 板块下的信息开启或关闭，会影响成员信息的填写与补充——例如要求成员提供哪些链的钱包地址、是选填还是必填。

Profile（所有人）

  • Name 可编辑（最长 50）
  • Account Email 只读
  • Reset Password 打开已登录改密弹窗
  • 管理员点右下角 Save 只更新姓名
  • 成员额外显示：
    • Position（可选，最长 50）
    • EVM Wallet Address（通常必填）
    • 以及组织开启的 Solana / NEAR / Tron / Slack / Telegram
    • Save 一次提交姓名与成员资料（职位、钱包、Slack / Telegram）

Organization（仅管理员）

  • Organization Name、可选 Logo URL（规则同注册）
  • Add Member / Invite（与 Team 相同）
  • Save 更新名称和 Logo，侧边栏会同步变化

Integration（仅管理员）

改动立即保存，没有总的 Save。

Channel of Notification

  • Email：锁定为 Required
  • Slack：开关 + Required / Optional。打开后会跳转 Slack 授权，完成后自动连接。Telegram 暂未开放。

Wallet Address

  • EVM Address：锁定 Required，无开关
  • SOLANA / NEAR / Tron：开关 + Required / Optional（关时下拉禁用）

这些设置决定：Add Member 表单、邀请 Profile Setting、成员 Settings 里出现哪些字段、哪些必填。

9 高级部分（Advanced）

9.1 角色与权限

系统只有两种角色：

角色 英文标识 如何获得
管理员（Admin） admin 注册组织后成为该组织管理员
成员（Member） user 通过组织发来的邀请链接加入

管理员可以管理场景表单、发起付款、维护团队与组织设置；成员只能查看自己的收支、发起单笔付款和提交付款申请。

侧边栏逐项对照见 3.1 侧边栏。

9.2 成员端全流程

成员从邀请链接加入（见 2.4 邀请加入），登录后侧边栏只有 Overview、Payment、Expenses、History、Settings。

9.2.1 成员 Overview

问候 Hi! {姓名}。

  • Total Income / Payment Transaction
  • Total Payout / Payout Transaction
  • Payment Volume 柱状图：Income 绿、Payout 紫；Daily / Weekly / Monthly
  • Open Requests（最多 6 条）：显示用途，View All 打开全部申请
  • Recent Payments（最多 5 条）：Type、Purpose（memo），链到 History

9.2.2 成员单笔付款

与管理员同一张单笔卡片，但：

  • 没有 Payment by Form 标签
  • 通讯录是个人收款人，可增删改
  • 仍跳转托管结账页完成付款

Zcash 透明 / Unified 地址可收 ZEC；zs1 不可用。

9.2.3 申请付款 Request Payment

侧边栏文案为 Expenses。页内标签：

  • Request Payment
  • Requests

表单：

  1. Request for（必填，最长 50）：付款人看到的短名称。问号提示：Short name the payer sees on the request.
  2. Description（可选，最长 200）：如发票说明或附件链接。
  3. Payment setting：金额（最多 6 位小数）+ 收款代币。
  4. Receiving Address：优先用该链已保存的默认地址，否则用当前连接钱包。可开 Save as default。没有「私下收款」模式。

Generate Payment Request 成功后弹出链接：

{站点}/pay/form?batch_id={batch_id}

这个链接是给管理员付款时使用的。Copy Link 复制链接，表单随后清空。

生成前会校验：组织存在、已选代币、金额为正、有用途、地址匹配所选链。

9.2.4 我的申请 Requests

每页 10 条。列：

列 含义
Request for 用途、复制链接、创建时间
Request to pay amount SYMBOL · Chain
Receive Address 你的收款地址
Paid Address 实际付款地址
Paid Time 支付时间
Status Pending / Complete / Failed

Status：

  • Pending：pending / created / processing（蓝）
  • Complete：completed（绿）
  • Failed：failed / expired（红）

有交易哈希时，Status 可点开浏览器查看。申请不能撤回或停用。

9.2.5 成员 History / Settings

见 7 历史记录、8 设置。History 多 Type 与金额正负色。Settings 只有 Profile。

9.2.6 成员不能做什么

  • 不能使用批量付款、Payroll、费用管理台、奖金、运营分类和团队功能
  • 不能启用或停用运营分类，也不能修改组织设置
  • 单笔付款的通讯录是自己的联系人，不是全员名单
  • 申请链接需要管理员实际打款后才会到账

9.3 限额、链与常见注意

输入限额

项目 限制
姓名 / 职位 / 组织名 最长 50
登录邮箱 最长 100
密码 8–50
邀请码 最长 10
Logo URL 最长 500，http(s)
金额小数 最多 6 位
Memo / Purpose / Description 最长 200（申请用途最长 50）
CSV / Excel 导入 最多 500 行
验证码冷却 60 秒

付款方式对照

场景 谁操作 钱包

Team Pay Now 管理员 同上

network 可用常用别名（如 ethereum → eth、matic → pol、arbitrum → arb）。Token 与 network 必须是系统支持的组合。

  • 产品自托管：私钥留在你的钱包扩展 / Noir Wallet 中。
