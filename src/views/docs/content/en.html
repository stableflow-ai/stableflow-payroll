Stableflow Payouts

User Guide

Stableflow Payouts is a lightweight financial management platform for organizations and teams. Its core payment capabilities are single payments and batch payments, used to centralize funds, payouts, and member collaboration. The platform has two sides: organizers manage and pay out payroll, reimbursements, and bonuses, while members submit reimbursements and track their income.

1 Platform overview

Stableflow Payouts lets a business send stablecoins from one paying wallet to addresses on EVM, Near, Solana, Tron, and Zcash. Paying with native Zcash requires Noir Wallet.

You stay self-custodial: single payments jump to hosted checkout, while payment by form is signed in the app.

On first use, complete account verification on the register page and create an organization — you enter the platform as an organizer. Members join through the invite link an organization sends them. If the organization has Google sign-in enabled, either can use a Google account instead.

3.2 Overview

The Overview page is built from key amounts / metrics, a time-series line chart, and a recent activity panel on the right. It is designed for a daily starting check: see how total amounts move day to day, week to week, and month to month, scan what is waiting or active, then move into Payment, Expenses, or History to handle it.

  1. Organization summary — name / logo, owner, team count, Update Settings.
  2. Payments — Total Payment, Number of Payments, View all to History. Area chart: Daily / Weekly / Monthly and Volume / Transaction.
  3. High Priority — rows to Payroll, Expense, or History (failed payouts).

4 Payments

Pay offers two modes: Single Pay and Form Pay. The former suits one-off payments with information you already have; the latter suits cases where payment details are collected or entered through an on-page form. Which one to use should follow your organization's process and the fields the page actually offers.

A single payment jumps to hosted checkout; payment by form needs a connected wallet and is signed in the app.

4.1 Connect a wallet

Top right of the page:

  • Disconnected: Connect Wallet
  • Connected: chain icon + shortened address; click to manage

Payer chain kinds:

  • EVM (RainbowKit): Ethereum, Base, Arbitrum, Optimism, Polygon, BNB Chain, Avalanche, Gnosis, Scroll, X Layer, Berachain, and others in the registry
  • Near
  • Solana
  • Tron
  • Zcash (Noir Wallet): display / quote payer is shielded Unified (u1); refund is transparent (t1 / t3)

Single Pay (/pay) does not use a wallet in this app. Submit opens hosted checkout.

Form Pay and Pay Now on Payroll / Expense / Bonus / Operations need a wallet that matches You Pay, and you sign here.

Zcash:

  • Native Zcash origin only when the form has one recipient. With several recipients, Zcash is visible but disabled: Zcash does not support batch payments yet.
  • Confirming inbound ZEC is not spendable: ZEC is still confirming in Noir Wallet. Wait until it is spendable, then retry.
  • Recipients can be t1 / t3 or Unified u1 for ZEC. Sapling zs1 is rejected.

4.2 Single Pay

Admins can switch between two modes:

  • Single Pay → /pay
  • Form Pay → /pay/form

Members do not see the tabs.

A single payment starts by entering a recipient wallet address, or by picking someone from the Team address book, then choosing the receiving token and chain. You can record a purpose for the payment, visible only to the payer, to look back on later. With notifications on, the recipient can be told by email or Slack.

Form

One card:

  1. Recipient
    • Search or paste an address.
    • Address book: team members with a wallet (scroll to load more), select-only. Wallet order: EVM → Near → Solana → Tron. Pasting any of a member’s wallets still matches the name chip.
    • Changing to another chain clears the token, then defaults USDT → USDC → first available token on that chain.
  2. Amount + receiving token (max 6 decimal places).
  3. Purpose / memo (optional, max 200).
  4. Notify Recipient — off by default. On shows an editable email (prefilled from a matched member). An empty or invalid email while the switch is on blocks send.

Empty CTA: Starts from adding recipient. When ready: Send Payment.

After send

Submitting jumps to hosted checkout to complete the payment.

Pay Now in a Team row starts a single payment too: name and wallets prefilled, address still editable.

4.3 Form Pay

Admin only.

Depending on your business needs, first manage the scenario forms under Operations — for example, import and manage a Payroll form. Then you can use form payment: pick the matching form and pay the batch.

The same form is used for the Pay Now dialog on Payroll / Expense / Bonus / Operations.

Choose a form

Form lists current payables:

  • Payroll
  • Reimbursement
  • Bonus
  • Dynamic Operations (Office and others; labels prefer catalog names)

Opening a member’s request link preselects the matching expense batch.

Empty CTA: Select Category.

You Pay

Pick paying wallet, chain, and token. The quote fills You Pay and Est. Cost with the total.

Details next to Total Valued opens a drawer: total, recipient count, and Next Pay-date for payroll. Each row: name, email, address, payout preference, Amount, Net Pay.

  • Payroll only can Edit / Save Net Pay (max 6 decimals); save writes changed rows only, and closing the drawer or switching forms drops unsaved edits.
  • Expense / Bonus / Operations Details are read-only.
  • After the first split batch is paid, Details becomes read-only.

Notify Recipient

Off by default. On shows {n} Email. Click opens Notify Recipients: master switch, name + email + checkbox per person. All start selected. Missing email shows -. Turning the card switch off, the drawer switch off, or unchecking every row turns Notify off.

CSV import does not supply notify emails; only rows that already have an email can be notified.

Send

  • One batch: Send Payment, then sign in your wallet.
  • Split batches (about 50 txs per batch): each batch shows Pay Now (Batch Payment n + source amount), signed one batch at a time. The form stays open until every batch is paid.
  • When your allowance is short: Insufficient approval. Refreshing the quote.

4.4 Payment result

Hosted checkout returns to this page after success.

On success: Payment sent plus amount. Otherwise Payment in progress.

Shows amount, token, network, recipient, time, and source / destination tx hashes (explorer links).

4.5 After payment, and batch limits

Once a batch payment is submitted, transaction results are listed one by one until every pending item in the form is done. If some transactions failed, pay them again from the form manager.

⚠️ Note: A single batch payment is limited to 50 transactions. If the form has more than 50 pending items, the payment is automatically split into several actions.

Chain, limit, and import-template details are in 9.3 Limits, chains, and notes.

5 Operations

Stableflow Payouts offers three payment scenarios by default — Payroll / Expenses / Bonus — and can enable more. Extra scenarios come from the operations catalog.

5.1 Payroll

The Payroll page carries the key parameters, the monthly payroll trend chart, recent payouts, payroll management and editing, and payroll payment history. On screen: stats, Daily / Weekly / Monthly chart, and recent payouts — a row opens History.

Next Payroll

Next cycle table; email after address.

An empty list shows the create options:

  • Download Template — Excel (.xlsx) with token / network dropdowns.
  • Import CSV — from a local file or Google Docs, CSV or Excel, max 500 rows. Import opens Add Payroll with the rows.
  • Add Payroll — empty Add Payroll drawer.

For a first payroll edit, you can edit and import from the platform's template, or enter the form by hand.

Pay date: First day of month, Last day of month, Day of month (1–31; 1 and 31 mean first / last day).

Save stays on Next Payroll. Edit can change rows, add rows, and delete ids.

Pay Now opens Form Pay titled {Month} Payroll, carrying the current Net Pay. Before payday the button reads Not payday yet and does not open.

Payroll History

Paginated. Export CSV.

View Details opens a right drawer; the export next to it downloads that run.

Status: Failed, Expired, Paid, Pending. Failed / Expired can be retried with Pay Again.

To trace payroll operations, cross-check the Payroll records against History.

5.2 Expenses

Expenses handles team reimbursement and expense payment management. Organizers batch-import or manually enter expense items in Open Expense; the items in Request Payments come from member requests, which the organizer can review — checking the amounts and the stated purpose — and then approve for payment.

When there are open requests, the sidebar shows a count badge.

Same pattern: stats, chart, recent payouts (a row opens History).

Open Expense

Grouped by batch. One-member batches show Title / Name / Purpose / Description / Address / Email / Payout Preference / Amount. Multi-member batches collapse; Purpose / Description / Address / Email show - until expanded. http(s) URLs in Description are receipt links (confirm, then new tab).

Pay Now on the batch header pays the whole batch.

An empty list offers Download Template, Import CSV and Add Expense; with batches, the toolbar offers the same three.

Import: max 500 rows, CSV or Excel. Save returns to Open Expense.

Request Payments

One person per row. Empty: No payment requests. Pay Now pays that row’s entire batch, not only the row.

Expense History

Search and date range. Export CSV uses the current filters. Description / Receipt matches Request Payments.

Status: Failed, Expired, Paid, Pending. Failed / Expired can use Pay Again.

5.3 Bonus

Bonus supports batch import and one-by-one entry, to lay out the team's bonus forms.

⚠️ A bonus is often paid out in a project token. When entering a recipient wallet, check that the address can accept that token / chain.

Same layout as Expense: stats, chart, recent, open batches, history.

Empty open list: Download Template, Import CSV, Add Bonus; with data the same three appear. Import max 500 rows, Save returns to the open list.

Grouping matches Open Expense. Bonus column: one member shows amount symbol ($volume); multi-member expands per person while the header keeps the batch USD total. Description URLs are clickable.

A batch being paid shows Paying; otherwise it shows Pay Now.

History is per person: Name / Purpose / Description / Bonus / Address / Payout Preference / Amount / Status. Failed / Expired can Pay Again. Export CSV is available.

5.4 More scenarios (Manage Operations)

More scenarios appear by clicking the ⋯ (more) next to the Operations nav item — for example office running costs, procurement, outsourcing, or KOL marketing. You can preview that module's form template, and enable it; once enabled, the module joins the main menu as a frequently used form.

Categories that may appear in the catalog:

  • Office
  • Procurement
  • Outsourcing
  • KOL&MKT
  • Grants
  • OTC Treasury

plus any other category in the catalog.

More Categories

The ⋯ on Operations opens the categories drawer.

Each card can preview a template: hover View Template, click the card to open it, and go back to the grid. Templates are sample rows; nothing is paid.

  • Not added: card Switch or template Add Category adds it.
  • Added: the switch enables or disables the category.
  • Only enabled categories appear in the sidebar; disabling removes the category from it.
  • Add Category on a template closes the drawer and opens that category.

Category page

While a category is not enabled, the page shows its description, template and Add Category. Once enabled it has two tabs: Payments and Payout History.

Layout matches Expense: stats (Total Payment / Number of payments), chart, recent, open batches, history. Copy uses the catalog name (Add Payment / Import).

Empty open list: Download Template, Import CSV, Add Payment. Import columns: recipient,email,amount,token,network,memo, max 500 rows.

History can filter by date but has no search. Failed / Expired can Pay Again. Pay Now pays that batch via Payment by Form.

6 Team

Team members can be added by an organizer, or invited through the organization. An invited person who activates the platform through the invite link is automatically placed under that organization; a new user needs to register an account by email to join.

Search by name, email, position or EVM address, over a paginated table (10 per page). Columns: Name, Position, Email, Wallet. Wallet prefers EVM, then Near, Solana, Tron.

Same buttons as Settings → Organization:

  • Add Member — member form.
  • Invite — copy the invite link to send to a member.

Add / Edit

Fields follow Integration:

  • Name always (required, max 50)
  • Position optional (max 50)
  • Wallet and notification fields only when that channel is on; Required must be filled. EVM is required.
  • A filled wallet must pass that chain’s address check (including Tron).
  • Telegram / Slack are saved when filled; editing prefills the saved values.

Row menu

  • Edit
  • Pay Now — start a single payment
  • Remove — confirm, then delete

7 History

Admins see the whole organization; members see only their own income and payouts.

History is for looking back at past actions. It is the main place to check a payment's status, confirm something was submitted, and reconcile payroll, reimbursement, or bonus records. Look here first when:

  • a payment's page state is unclear
  • you suspect a duplicate submission
  • you need to trace the basis for a business decision
  • you need to confirm the final outcome of an action

Top bar

  • Search
  • Date range (default last 30 days)
  • Export CSV (current filters)

Card filters

Members also have Type: All / Income / Payout.

Then: Source Network, Source Token, Destination Network, Destination Token, Status (All / Created / Processing / Completed / Failed / Expired).

Any filter change resets to page 1. There is no amount filter.

Table

Amount, Source, arrow, Received, Destination, From, To, Time, Status.

Member rows prepend Type (Income / Payout) and sign Amount: green + income, red - payout.

Source / Destination show token logo and SYMBOL · Chain. From / To copy the truncated address and open the explorer.

Status: Completed green; Failed / Expired red; Created / Processing black.

8 Settings

Settings is where you configure organization information and which member fields are required. Toggling an item in the Integration section changes what members are asked to fill in — for example, which chain wallet addresses they provide, and whether each is optional or required.

Profile (everyone)

  • Name editable (max 50)
  • Account Email read-only
  • Reset Password opens the signed-in dialog
  • Admin Save updates name only
  • Members also see:
    • Position (optional, max 50)
    • EVM Wallet Address (usually required)
    • Solana / NEAR / Tron / Slack / Telegram when the org has those channels on
    • Save posts name and member profile

Organization (admin)

  • Organization Name, optional Logo URL (same rules as register)
  • Add Member / Invite (same as Team)
  • Save updates the name and logo; the sidebar follows

Integration (admin)

Changes save immediately. There is no Integration Save button.

Channel of Notification

  • Email: locked Required
  • Slack: switch + Required / Optional. Turning it on starts Slack authorization and connects automatically. Telegram is not available yet.

Wallet Address

  • EVM Address: locked Required, no switch
  • SOLANA / NEAR / Tron: switch + Required / Optional (dropdown disabled when off)

These settings drive Add Member, invite Profile Setting, and member Settings fields.

9.2.3 Request Payment

Sidebar label Expenses. In-page tabs:

  • Request Payment
  • Requests

Form:

  1. Request for (required, max 50) — short name the payer sees. Tooltip: Short name the payer sees on the request.
  2. Description (optional, max 200) — invoice detail or attachment link.
  3. Payment setting — amount (max 6 decimals) + receiving token.
  4. Receiving Address — prefers a saved default for that chain, else the connected wallet. Save as default is a toggle. No private-receive mode.

Generate Payment Request shows:

{origin}/pay/form?batch_id={batch_id}

That link is what the admin uses to pay. Copy Link copies it; the form then resets.

Generate checks: organization present, token selected, amount positive, purpose filled, address matches the token chain.

9.2.4 My Requests

10 per page.

Column Meaning
Request for Purpose, copy-link, created time
Request to pay amount SYMBOL · Chain
Receive Address Your receiving address
Paid Address Address that paid
Paid Time When it was paid
Status Pending / Complete / Failed
  • Pending: pending / created / processing (blue)
  • Complete: completed (green)
  • Failed: failed / expired (red)

When there is a tx hash, Status opens the explorer. Requests cannot be withdrawn or disabled.

9.2.5 Member History / Settings

See 7 History and 8 Settings. History adds Type and signed amount colors. Settings is Profile only.

9.2.6 What members cannot do

  • Cannot use batch payment, Payroll, the expense console, Bonus, operations categories or Team
  • Cannot enable or disable operations categories, or change organization settings
  • The Single Pay address book is your own contacts, not the full team list
  • A request link is only paid once an admin actually pays it
